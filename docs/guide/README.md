# 智能家居 Agent 教程

> **写给谁**：想学 AI Agent 开发、但被 "Agent" 这个词绕晕过的人。
> 你只需要会 Python（类、装饰器、类型注解），知道"大模型是个能聊天的 API"就够了。
> 向量数据库、RAG、ReAct、状态机、Checkpoint 这些词，遇到时会从零解释。
>
> **代码版本**：`HEAD = e7d1113`（011 工程收口）。全文行号引用均按此版本核对。
> 测试基线：**264 passed, 383 subtests passed**（实测）。
> 工作树里另有两处尚未提交的修复（`memory/summarizer.py`、`agent/telemetry.py`），
> 涉及它们的章节只写符号名不写行号，见第 12、15、19 章。
> **读法**：第 0 章必读（十分钟跑起来）。之后每章都是"上一章留下了什么问题 → 这一章怎么解"，
> 建议顺序读一遍，再当参考手册查。

这不是一本 LangGraph API 手册（那种东西官网就有，而且更新更快）。这本教程讲的是
**一个真实项目在十三次迭代里踩过的坑，和每个设计决策背后被否决的那些方案**。
每一章都会诚实写出当前实现的局限——包括还没修的安全洞。

## 这个项目是什么

一句话：**你对着终端说人话，它去控制家里的灯、空调、窗帘、门锁、加湿器**。

```
你: 打开客厅灯，把空调调到 26 度
Agent: [规划 2 步] → [执行] → [核对真实设备状态] → 好了，客厅灯已开，空调 26 度制冷

你: 我明天早上 7 点起床，提前把卧室暖起来
Agent: 要创建一条定时例程，明早 6:30 开卧室空调到 24 度。确认吗？(y/n)

你: 把大门打开
Agent: ⚠️ 这是高风险操作，需要你确认：解锁前门。(y/n)
```

设备全部跑在模拟器上，不连真实硬件——所以你可以放心地把它玩坏。

## 三条阅读路线

**A. 我只想快点跑起来玩玩**
第 0 章 → 第 1 章 → 附录 A 挑几个实验做。

**B. 我要系统学 Agent 开发**（推荐）
第 0 章到第 19 章顺序读。每章的「动手试一试」都真做一遍——这本教程里所有命令都是实际跑过的。

**C. 我在做自己的 Agent，来找解法**
按问题查：

| 你的问题 | 去哪章 |
| --- | --- |
| 模型老是调错工具 / 参数瞎填 | 3、5 |
| 模型说做完了其实没做 | 6 |
| 危险操作要人确认，但进程重启后暂停就丢了 | 7 |
| 怕模型被诱导去动别人的数据 | 8、11 |
| 太慢、太贵，每句话都在调 LLM | 9、15 |
| 要并发查一批东西 | 10 |

## 开发环境（速查，详见第 0 章）

```bash
# 固定用这个 Conda 环境，不要 uv、不要新建 .venv
F:\Software\Anaconda\envs\langgraph\python.exe

# Windows 下运行任何会打印设备名或 emoji 的命令都要加这个，否则 UnicodeEncodeError
PYTHONIOENCODING=utf-8 "F:/Software/Anaconda/envs/langgraph/python.exe" -m pytest -q

# 启动 CLI（需要 .env 里的 LLM_API_KEY）
python -m src.main
python -m src.main --trace    # 额外显示路由/记忆判断等诊断事件
python -m src.main --admin    # 以家庭管理员身份运行
```
