# 写作与维护约定（内部）

这份文件是 `docs/guide/` 全部章节的统一格式基准。**改教程之前先读它**，
新增/重写章节必须照这套结构来，否则各章风格会漂移成第二个 5000 行的 `docs/tutorial.md`。

---

## 1. 读者是谁

- 会 Python（类、装饰器、类型注解），知道"大模型是个能聊天的 HTTP API"。
- **不知道** Agent / ReAct / LangGraph / LangChain / Checkpoint / RAG / MCP / 状态机 / 向量检索是什么。
- 所以：**每个术语第一次出现必须用一句大白话解释**，再给英文原词。
  例：「Checkpoint（检查点）——把对话的全部中间状态存进数据库，进程重启后能原地续上」。
- 不要写"如你所知""显然"。读者不知道，也不显然。

## 2. 每章固定五段结构

```markdown
# 第 N 章 标题

<一句话说这章解决什么>

## N.1 要解决什么问题
上一章留下的具体痛点 → 一个能让读者共情的失败场景（最好是真实对话/报错）
## N.2 代码怎么写的
带文件路径和行号的代码走读。先给全景（图/流程），再拆细节
## N.3 关键设计决策
"为什么这样而不那样"。列出被否决的方案和否决理由
## N.4 动手试一试
可复制粘贴、真的能跑的命令 + 预期输出
## N.5 踩坑与局限
### 坑一：xxx
### 坑二：xxx
（诚实写出当前实现的不足，不要粉饰）

**这一章的局限**：...
**下一章的问题**：...   ← 必须有，负责把读者交给下一章
```

标题层级：章标题 `#`，小节 `##`，坑/实验 `###`。**全章只有一个 `#`**。

## 4. 事实纪律（最重要的一条）

**教程里的每一个行号、类名、函数名、字段名都必须是读过代码确认的。** 写之前先
`Read`/`Grep` 对应文件，不要凭印象或凭 `CLAUDE.md` 的转述写。

- 引用格式：`src/agent/graph.py:343`（单行）或 `src/agent/graph.py:343-360`（范围）。
- **拿不准行号就只写符号名**（`graph.py:task_router()`）。宁可少一个行号，不能错一个行号。
- 贴代码片段时保持原文，不要"顺手美化"。省略中间部分用 `...`（同时注明省略了什么）。
- 命令行示例统一用项目约定：

  ```bash
  PYTHONIOENCODING=utf-8 "F:/Software/Anaconda/envs/langgraph/python.exe" -m pytest -q tests/test_xxx.py
  ```

  Windows 下漏了 `PYTHONIOENCODING=utf-8` 会 `UnicodeEncodeError`。
- **写进"动手试一试"的命令必须真的执行过**，把真实输出贴上去（长输出可截断并标注）。
  跑不起来的实验就删掉，不要留下读者复制后报错的坑。

## 5. 语言风格

- 全中文。技术标识符（`build_graph`、`ExecutionPlan`）保持原文不译。
- 用短句。一段讲一件事。
- **讲"为什么"重于讲"是什么"**。代码本身能回答"是什么"。
- 允许并鼓励第二人称（"你会发现……"）和真实吐槽（"这个坑我踩了两小时"）。
- 不要复述 `CLAUDE.md` 的句子。`CLAUDE.md` 是给改代码的人看的结论，教程要展开成推导过程。

## 6. 篇幅

目标 **250~450 行**，硬上限 **500 行**。但规则要跟现实一致 —— 约定和文件对不上，
正是上一版教程失控的起点，所以这里如实登记当前状态（`wc -l`，实测）：

| 区间 | 章节 |
| --- | --- |
| 250~450（达标） | 00~06、13、15、16、18、19、附录 A、附录 B |
| 450~500（可接受，主题本身大） | 08(450)、11(450)、09(455)、14(480)、17(489)、12(493) |
| **超 500（需登记理由）** | **10(524)、07(627)** |

超标两章的理由，写在这里而不是留给下一个人猜：

- **第 7 章 627 行** —— 审批是全书唯一"要跨进程存活"的机制，7.2 拆了 8 个小节
  （`interrupt()` 语义 / Checkpoint 落盘 / 恢复时从头重跑 / fail-safe / 两个风险等级 / 三处审批点）。
  5 个坑里有 2 个是安全问题（坑一"节点重跑导致重复执行"、坑四"MCP 绕过全部审批"），
  这两个删掉读者就会写出不安全的代码。**结论：不拆，但它是下次动这本教程时第一个该拆的。**
- **第 10 章 524 行** —— `Send` + reducer 是 LangGraph 最密集的坑区，
  实验 A 是全书唯一**不依赖本项目任何代码**的独立可跑实验（只要装了 langgraph），价值高于篇幅。

**要拆的时候怎么拆**：按 `N.2 代码怎么写的` 的小节切，拆出的新章沿用同一套五段式，
不要拆成"7 章上/下"这种没有独立主题的形式 —— 读者查东西时找不到入口。

**不要为了压行数删掉已实测的实验或真实输出**。优先级是：
真实证据 > 篇幅规则。宁可在上表里多登记一行，也不要把验证过的内容换成没验证过的概述。

## 9. 改完怎么自查（三层机器校验）

人工通读查不出行号漂移 —— 全书 **371 处**引用，一次通读必漏。
下面三层都是十几行的一次性脚本，写在临时目录里跑完即弃，比雇人校对可靠得多。
**改动教程后至少跑第 1、2 层。**

| 层 | 查什么 | 判据 |
| --- | --- | --- |
| 1. 完整路径引用 | `src/agent/graph.py:343` 这类 | 文件存在 + 行号不超界；再检查引用前那个反引号符号名是否出现在 ±4 行内（漂移告警） |
| 2. 裸行号引用 | `` `:80` `` / `` `:53-63` `` 这类，按约定指代上文最近提到的文件 | 同上。**注意归属是启发式的**：要同时接受完整路径和"裸文件名 + 行号"（`capabilities.py:422`）两种上下文，否则会把 `graph.py` 的引用错记到别的短文件上，产生几十个假阳性 |
| 3. 反引号符号存在性 | `` `SimulatorBackend` `` 这类标识符在 `src/` `tests/` 全文里搜不到 | 搜不到就人工看一眼。**这一层专治幻觉符号** —— 读者复制一个不存在的类名会直接 `ImportError` |

第 3 层必然有一批**合法的"搜不到"**，别急着改，先归类：

- 占位符（`_on_xxx`、`control_xxx_mcp`）
- 框架符号（`CompiledStateGraph`、`GraphRecursionError`、`trim_messages`）
- **刻意提到的已删除 API**（`set_registry` / `set_automation_runtime`，见第 4、18 章）
- 提议的改法（第 16 章建议给 `unlock` 加 `approved_by` 参数）
- 描述"缺失的东西"（第 15 章说本项目**没有**贯穿的 `trace_id`）
- 实验里要你新建的（第 17 章香薰机的 `control_diffuser` / `mist_on`）

上一轮校验的实测结果：**143 处完整路径引用 0 硬错误 0 漂移；228 处裸引用仅 1 处告警且是假阳性
（`:8765` 是 SSE 端口不是行号）；21 个"搜不到"的符号全部属上面六类，零幻觉。**
下次改完，拿这组数字当基线对比。

一件脚本查不出来的事：**语义是否用对**。符号存在不代表用法正确。
所以涉及机制表述的改动，仍然要回去跑对应那一章的实验 —— 这也是"命令必须真跑过"那条约定的用处。
